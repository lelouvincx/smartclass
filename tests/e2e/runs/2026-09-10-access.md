## Transient observations and tool limitations

The first WS-03 post-disable navigation unexpectedly reached sign-in instead of the membership-status screen. Fresh sign-in showed the correct disabled state. After restore and a second disable, the existing-session check passed with `/api/auth/me` HTTP 200. The original response status was unavailable, so neither HTTP 500 nor an authentication bug is established.

Before submitting the global block, another English refresh unexpectedly reached sign-in. Resource Timing then contained no API entries. A fresh form sign-in succeeded before the actual global block. The parent reported intermittent local D1/workerd errors elsewhere, but this run did not capture a matching 500 response. These observations remain unconfirmed environment or application transients, not confirmed access-control defects.

Managed-command interruptions were recovered rather than counted as application failures:

- `find role ... --name` was refused by the lifecycle wrapper, although the browser guide documents it
- a `:has-text(...):visible` selector failed; later actions used inspected native CSS
- an offscreen disable click failed; scrolling the actual element into view before clicking worked
- the wrapper refused `scrollintoview`; supported `eval` with DOM `scrollIntoView` provided scrolling only
- an unnecessary session-level `dialog accept` failed because local disable had already completed without a native dialog
- initial sign-in inputs were unexpectedly empty after an early command chain; inspecting lengths and filling again resolved browser form validation

One recovery sequence used a shell success exit as its condition and started a replacement while the preceding session reported `cleanup-pending`. The next recovery verified the original session closed before replacement tab work continued. This was an execution sequencing error, not a browser or application defect. Later shutdowns checked terminal state explicitly.

No automated provider matrix, Google login, exhaustive per-state viewport matrix, keyboard-only audit or full test suite ran. Representative visual coverage is listed below. Screenshots corroborate rendered states; the executed interactions establish behavior.
